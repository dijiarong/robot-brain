## 背景

第三次迭代已经完成持久化任务队列与轮询式 scheduler，但仍需要调用方主动执行 `run_next()`。项目缺少一个可以常驻运行的服务进程，也缺少便于人工操作和观察状态的接口。

本次迭代将 scheduler 包装为独立服务层，提供后台循环、HTTP API、WebSocket 状态推送、轻量状态页面和优雅停机。

- [x] 支持显式 `start()` 和 `stop()`。

## 复盘

已完成本地服务化闭环：

- 增加 `AgentService`，负责后台轮询、事件广播、并发串行化和优雅停机。
- 增加 FastAPI app 工厂，使用 lifespan 启停服务，避免 Web 框架侵入认知与调度模块。
- HTTP API 覆盖健康检查、状态查询、任务提交、列表、单任务查询、取消、人工确认、事件入口和急停重置。
- WebSocket `/ws` 会在连接后立即发送状态快照，并推送后续调度与控制事件。
- 根路径提供自包含状态页面，无需前端构建步骤。
- 页面展示服务状态、电量、急停、位置和任务列表，并提供排队任务、样例告警、急停和重置按钮。
- 增加 Uvicorn 启动入口、`robot-brain-service` 命令和 `examples/run_service.py`。

遗留问题：

- 当前只适合本机可信环境，尚未加入身份认证、权限控制和 HTTPS。
- 服务默认监听 `127.0.0.1:8000`，尚未增加 CLI 参数或环境变量配置。
- 状态页为轻量内嵌页面，没有任务筛选、历史详情和确认弹窗。
- 后台循环会持续保存轮询快照，后续需要快照去重和清理策略。
