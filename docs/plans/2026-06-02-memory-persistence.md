# 第一次迭代：记忆持久化

## 基本信息

- 日期：2026-06-02
- 状态：已完成
- 负责人：待定

## 背景

当前项目已经具备记忆接口和内存版实现，但还没有可跨进程保留的数据存储：

- `ShortTermMemory` 使用有容量限制的内存队列，保存最近事件和决策。
- `LongTermMemory` 默认使用 `InMemoryExperienceStore`，只保存命令执行后的目标、结果和摘要。
- `CheckpointStore` 使用内存字典，保存等待人工确认的动作。
- 运行时尚未保存完整的会话消息，也没有按 `thread_id` 回放历史的能力。

因此，进程重启后，最近事件、长期经验、对话上下文和待确认动作都会丢失。记忆存储应当优先于继续扩展更多技能，作为骨架完成后的第一次正式迭代。

## 目标

- [x] 使用 SQLite 增加本地持久化存储，默认数据库路径可通过配置覆盖。
- [x] 定义会话和消息模型，按 `thread_id` 保存用户命令、运行结果、必要的系统事件和时间戳。
- [x] 为长期经验实现 SQLite 存储，保留现有 `ExperienceStore` 可替换接口。
- [x] 为待确认动作实现 SQLite checkpoint 存储，使进程重启后仍可恢复。
- [x] 保持短期记忆为有界工作记忆，并支持从最近会话记录恢复必要上下文。
- [x] 补充数据初始化、基础查询和重启恢复测试。

## 本次边界

- 第一版优先使用 Python 标准库 `sqlite3`，不引入外部数据库服务。
- 第一版提供基础关键词检索；向量检索和 embedding 留到后续迭代。
- 第一版记录文本和结构化结果，不保存图片、音频或原始传感器大文件。
- 第一版不处理多机器实例之间的数据同步。

## 实施方案

1. 在 `config/settings.py` 增加数据库路径配置，例如环境变量 `RDB_MEMORY_DB`。
2. 在 `robot_brain/memory/` 增加 SQLite 初始化和存储实现，至少包含：
   - `threads`：会话元信息。
   - `messages`：按会话保存角色、内容、消息类型、时间戳和可选结构化元数据。
   - `experiences`：保存目标、结果、摘要和时间戳。
   - `checkpoints`：保存待确认动作及其所属 `thread_id`。
3. 调整运行时，在接收命令、产生结果、触发中断和创建或消费 checkpoint 时写入存储。
4. 启动运行时时加载当前会话需要的最近消息，并将其裁剪后送入工作记忆。
5. 保留内存版实现，方便单元测试和无落盘场景使用。

## 验证方式

- [x] 自动化测试：进程内创建新 runtime 后，仍能检索上一个 runtime 写入的经验。
- [x] 自动化测试：使用相同 `thread_id` 可以读取按时间排序的会话消息。
- [x] 自动化测试：等待人工确认的动作在创建新 runtime 后仍可恢复。
- [x] 自动化测试：短期记忆恢复后仍遵守容量限制。
- [x] 手动验证：运行示例并查询数据库；checkpoint 重启恢复由自动化测试覆盖。

## 复盘

已完成 SQLite 第一版持久化：

- 默认数据库路径为 `data/robot_brain.sqlite3`，可以通过 `RDB_MEMORY_DB` 覆盖。
- SQLite 后端统一维护 `threads`、`messages`、`experiences` 和 `checkpoints` 四张表。
- 运行时会记录命令、结果、系统事件和人工确认，并在首次使用 `thread_id` 时恢复最近会话到有界短期记忆。
- checkpoint 跨 runtime 恢复前会刷新一次感知，并再次经过安全校验。
- 内存版经验、会话和 checkpoint 实现仍然保留，便于测试和无落盘场景注入。
- 增加显式 `close()`，确保 SQLite 文件句柄在服务退出和 Windows 测试环境中可靠释放。

遗留问题：

- 当前长期经验仍使用基础关键词匹配，没有语义召回。
- 世界状态本身尚未持久化；checkpoint 恢复依赖恢复时的新鲜感知。
- 尚未加入数据迁移版本号和敏感信息清理策略。
