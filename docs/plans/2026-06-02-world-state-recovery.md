# 第二次迭代：运行状态持久化与重启恢复

## 基本信息

- 日期：2026-06-02
- 状态：已完成
- 负责人：待定

## 背景

第一次迭代已经使用 SQLite 保存会话消息、长期经验和待确认动作，但 `WorldState` 仍然只存在于进程内存中。进程重启后，机器人会丢失最近一次已知的位置、电量、环境对象、告警、急停状态和任务进度。

这会影响恢复后的安全判断，也会让 checkpoint 恢复缺少必要上下文。因此，在扩展更多技能或语义检索之前，先补齐运行状态快照。

## 目标

- [x] 在 SQLite 中新增世界状态快照表。
- [x] runtime 启动时恢复最近一次世界状态。
- [x] 在感知、动作执行、任务状态变化、急停和急停重置后保存快照。
- [x] checkpoint 恢复时组合历史快照与新鲜感知，再执行安全校验。
- [x] 保留可替换的状态存储接口和内存版实现。
- [x] 补充重启恢复与安全校验测试。

## 本次边界

- 当前按单机器人实例保存全局最新快照，不引入机器人 ID 和多租户隔离。
- 快照保存完整 JSON 状态，暂不做增量事件溯源。
- 启动恢复使用最近快照；真实传感器的新鲜感知仍然具有更高优先级。
- 暂不实现历史快照清理策略。

## 实施方案

1. 增加 `WorldStateStore` 接口、内存实现和 SQLite 实现。
2. SQLite 新增 `world_state_snapshots` 表，保存状态 JSON、原因、可选 `thread_id` 和时间戳。
3. 将状态存储注入 `AgentContext`，由编排节点在关键状态变化后写入快照。
4. runtime 创建时优先从状态存储恢复快照，显式传入 `world` 时以调用方数据为准。
5. runtime 在急停、急停重置和 checkpoint 恢复路径补充快照。

## 复盘

- 新增 `WorldStateMemory`、`WorldStateStore` 和内存版实现，保持存储层可替换。
